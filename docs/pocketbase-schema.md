# PocketBase schema

## Why we keep schema in git

`pb_data/` is local runtime data and should not be committed.

`pb_migrations/` is the schema history generated by PocketBase and should be committed.

This allows us to:

- recreate the project on another server;
- deploy changes predictably;
- see who changed the data model and when.

## Collections

We need 2 main collections:

1. `users` - auth collection for regular users.
2. `requests` - regular collection for user обращения.

PocketBase already has a separate admin area for superusers, so we don't create an admin collection.

## Collection 1: users

Type: `Auth`

Purpose: regular users sign in with login and password.

Fields:

- `username`
  - system field for login identity
- `email`
  - keep enabled, even if later you decide to log in only by username
- `name`
  - type `text`
  - required: `true`
  - this is the display name shown in the stream

Recommended auth options:

- Password auth: enabled
- OAuth2: disabled
- OTP: disabled
- MFA: disabled

API rules:

- List: `@request.auth.id != ""`
- View: `@request.auth.id != ""`
- Create: ``
- Update: `@request.auth.id = id`
- Delete: `null`
- Manage: `@request.auth.id = id`

Meaning:

- anyone can register a new user only if we keep `Create` empty;
- any authorized user can see users;
- a user can edit only their own profile;
- users can't delete accounts through public API.

If you want user creation only by admin, later we will lock public registration and create users from admin panel.

## Collection 2: requests

Type: `Base`

Purpose: store all user обращения in one shared stream.

Fields:

- `author`
  - type `relation`
  - collection: `users`
  - max select: `1`
  - required: `true`
- `message`
  - type `text`
  - required: `true`
- `category`
  - type `number`
  - required: `true`
  - min: `1`
  - max: `2`

API rules:

- List: `@request.auth.id != ""`
- View: `@request.auth.id != ""`
- Create: `@request.auth.id != "" && author = @request.auth.id`
- Update: `@request.auth.id = author.id`
- Delete: `null`

Meaning:

- only authorized users can see the stream;
- every authorized user sees all requests;
- a user can create only records on their own behalf;
- a user can edit only their own request;
- delete is blocked for regular users.

## Business rule

When a user creates a request:

- if `message` contains `привет`, then `category = 1`
- otherwise `category = 2`

We will implement this in the next backend/frontend step.

At the schema step we only create the `category` field.

## How to apply this schema

1. Start PocketBase:

```bash
./scripts/run-pocketbase.sh
```

2. Open Dashboard:

```text
http://127.0.0.1:8090/_/
```

3. Create or edit the collections exactly as described above.

4. After saving collection changes, PocketBase should generate files in `pb_migrations/` automatically.

5. Then commit `pb_migrations/` to git.
